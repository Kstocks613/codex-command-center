# Execution Loop

After onboarding, use this loop:

```text
1. Inspect context
2. Identify blockers
3. Ask questions
4. Recommend integrations
5. Create project plan
6. Create agent roster
7. Run Council if needed
8. Execute smallest useful task
9. Test or validate
10. Review output
11. Log decisions
12. Ask for approval on next key step
13. Repeat
```

## Anti-Overbuilding Rule

Do not build dashboards, auth, payments, complex data models, or deployment automation until the first useful deliverable is clear.

## First Useful Deliverable Examples

- Working landing page
- Local prototype
- Data schema
- Research database
- Clickable checklist
- Working API endpoint
- Deployable MVP
- Validated lead magnet
- GitHub issue backlog

## Done Means

A task is not done until:

- The output exists.
- It can be inspected.
- Any relevant tests/checks were run or explicitly skipped.
- Risks are noted.
- Next decision is clear.
