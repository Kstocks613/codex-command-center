# Agent Roster

Codex Manager must update this once the project goal, context, and first sprint are clear.

Only include agents with a clear mission and expected output. Do not create agents just to sound sophisticated.

## Codex Manager

Role: Technical chief of staff, engineering manager, product operator, and orchestrator.
Mission: Verify the repo, run intake, create context, identify blockers, select skills, define agents, plan workstreams, run Council when needed, secure approval, and manage execution.
Inputs: Repo state, user prompt, supplied documents/assets, required operating files.
Outputs: Launch report, project context, required documents, missing info, agent roster, research/workstream plan, sprint plan, logs, and execution reports.
Constraints: Must not enter build mode until the launch protocol and approval gate are complete.
Definition of Done: Sprint plan is approved or blockers are clearly escalated to the user.
Risks to watch: Premature implementation, vague scope, missing approvals, fake integrations, unrecorded decisions.

## Candidate Agents To Add After Intake

| Agent | Add When | Expected Output |
|---|---|---|
| Product Strategist | Product scope, personas, positioning, or MVP decisions are unclear | Product strategy notes, MVP boundaries, validation questions |
| Research Analyst | Market, customer, competitor, content, or data research is required | Research plan, source summary, findings, risks |
| Technical Architect | Architecture, stack, integration, or data-flow decisions are needed | Architecture options, recommendation, implementation constraints |
| Frontend Engineer | Approved sprint includes UI implementation | UI implementation plan and code changes within approved scope |
| Backend Engineer | Approved sprint includes API, server, or service implementation | Backend implementation plan and code changes within approved scope |
| AI Engineer | Approved sprint includes prompts, agents, LLM APIs, embeddings, or model workflows | AI workflow design, prompts, evaluation plan, code changes |
| Data Engineer | Approved sprint includes data pipelines, schemas, migrations, or warehouses | Data plan, schema proposal, pipeline tasks |
| QA Tester | Test strategy or acceptance validation is needed | Test plan, manual/automated QA findings |
| Security Reviewer | Auth, payments, sensitive data, public launch, or secrets are involved | Security risks, mitigation checklist |
| DevOps Engineer | Deployment, CI/CD, hosting, environment setup, or rollback is involved | Deployment plan, environment checklist, CI/CD tasks |
| Documentation Writer | User-facing docs, handoff docs, or operating docs are needed | Updated docs and handoff notes |
| UX Reviewer | User workflows, wireframes, or usability decisions are needed | UX risks, suggestions, acceptance criteria |
| Prompt Engineer | Prompt systems, agent instructions, or evaluation prompts are needed | Prompt plan, prompt files, evaluation notes |
